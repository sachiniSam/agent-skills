# asgardeo — promptfoo evals

Evaluates the `asgardeo` skill as a real agent skill discovered from a fixture
workspace. See [EVALS.md](../../../../../EVALS.md) at the repo root for the shared guide.

## Layer 1: stubbed CLI

The agent runs against a fake `asg` (`stub/asg.js`, Node builtins only) that prints
what the real CLI prints and keeps a small state file so `view`/`list` reflect
earlier `create` calls. Its `--help` texts are captured from the developer's
installed real `asg` at prepare time, and it rejects flags the real command does
not define. No org, login or credentials are needed, and nothing is created anywhere.

What this layer proves: the skill drives the CLI correctly (session check first,
right app type per framework, redirect URI registered = redirect URI wired, real
client ID and base URL copied into the code, secrets kept out of chat, the RBAC
pipeline in order). What it cannot prove: that Asgardeo accepts those commands
today, or that a browser sign-in completes. That is a live run against a sandbox
org, not part of this suite.

## Run

```bash
npm install
npm run eval                       # prepares fixtures, then runs the matrix 2 at a time
npm run eval:one -- "A/React"      # one scenario by description substring
npm run view
```

Requires Node >= 22.22, the real `asg` CLI on PATH (or `ASG_BIN=<path>`) so the
stub can serve its current help text, and `claude` logged in (no API key needed
locally). Each run bills usage (multi-turn agent + grader); run it on skill
changes, not on every save.

`fixtures/` is generated by `scripts/prepare.js` on every run and is gitignored:
the live skill is copied in with the repo's `tools/sync-fixtures.js`, the sample
apps are written fresh (so edits the agent made last run are gone), the stub is
installed on `bin/`, and help texts are captured.

The provider allows Bash, Write, Edit and WebFetch inside `fixtures/workspace`
so the agent can run the (stubbed) CLI, wire the SDK into the fixture apps and
read the docs quickstarts. Prompts tell it not to install packages.

## Layout

```text
promptfooconfig.yaml      provider + test file list
tests/triggering.yaml     activates on the right prompts, stays out of api-publish's way
tests/task-quality.yaml   one scenario per framework + tracks B, C, D, E, F
assert/asg-checks.js      deterministic checks over the agent's tool calls
assert/trace.js           appends the run's commands/file writes to the reply for the rubric grader
stub/asg.js               the stub CLI source
scripts/prepare.js        builds fixtures/ (skill copy, sample apps, stub, help texts)
fixtures/                 generated, not committed
```

## Adding a scenario

1. Add the sample project to `scripts/prepare.js` (a few `write()` calls).
2. Add a test in `tests/task-quality.yaml`: put the answers the skill would ask for
   (name, URL, scopes) in the prompt and approve the plan up front, pick `checks`
   from `assert/asg-checks.js`, and write one rubric for what can't be checked
   deterministically.
3. If the scenario needs a CLI command the stub doesn't know, add it to `stub/asg.js`.
